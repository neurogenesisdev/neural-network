# infra-docs — rules

## Never edit generated state

`*/state/*.md` is machine-generated by `<device>/collect/collect.sh`. Editing
one by hand reintroduces the failure this system exists to prevent: an
inference recorded as a measurement. To correct a state file, fix the system
or fix the collector, then re-run.

## Check decisions before proposing changes

Read `arch-thinkpad/decisions/_index.md` first. Several records exist to stop a
reasonable-looking change from being re-made — ADR-0005 rejects the DNS config
still written in the old PRD, ADR-0006 rejects podman named volumes even where
upstream recommends them, ADR-0002 forbids granting `hypr/**` in any enforced
AppArmor profile.

## State the basis for a claim

Never present a reasoned conclusion as an observed one. If it was not run and
seen, say so. Three false claims entered the previous documents this way.

Use the vault's three markers, in prose as well as in frontmatter: `measured`
(seen on this machine, with the command that showed it), `inferred` (reasoned,
not demonstrated), `inherited-unverified` (carried from an earlier document,
not re-checked).

## Look it up; never recall it

A command's flags, a config file's syntax, a tool's current behaviour: look it
up before writing it. Not "when unsure" — always. Confidence is not a signal
here; the three false claims above were all written confidently.

**Ask the tool first.** In that order, stopping at the first that resolves:

1. **The tool itself** — `<cmd> --help`, a subcommand's help, `mkinitcpio -H
   <hook>`, `sbctl verify --json`. This is first because it is the installed
   version answering about itself, with no version lag and no fuzzy match.
2. **`man.archlinux.org/man/<name>.<section>`** via WebFetch. Tracks the version
   actually packaged.
3. **The local ArchWiki** — `wiki-search <term>` (`arch-wiki-lite`), or the HTML
   in `arch-wiki-docs`. Installed at `20260702`, so it lags live by weeks; good
   for concepts and syntax, not for recent changes.
4. **Context7** `resolve-library-id` then `query-docs` — for upstream projects
   with their own doc sites: podman, restic, tailscale. Not for Arch-packaged
   system tools, which channels 1–3 cover better.
5. Nothing resolves it: do not write the flag or path. Write what the step must
   achieve, mark it `inferred`, and name the gap *and the lookup that would
   close it*.

**The ordering is load-bearing, and was wrong until 2026-08-23.** Twice in one
session the tool documented itself better than any page did. `mkinitcpio.conf(5)`
describes the `HOOKS` array but not a single hook, and explicitly defers to
`mkinitcpio -H`; a turn was spent on the wiki before anyone ran it. `sbctl
verify --json` retired two hours of increasingly careful glyph-parsing and had
been in `sbctl.8` the whole time. Reaching for prose documentation before asking
the binary is the expensive mistake, not the safe one.

**The live ArchWiki is unreachable programmatically.** `wiki.archlinux.org` is
behind Anubis, a JavaScript proof-of-work interstitial; every fetch returns
`Access Denied: error code <hex>` regardless of article, and `?action=raw` does
not bypass it. It is not a block, a rate limit, or a bad URL. Do not spend a
turn retrying it — go to channel 3. Measured 2026-08-23, see `state/notes.md`.

**Context7 fuzzy-matches and returns the wrong tool confidently.** Asked for
`sbctl` it offers SBCL, the Common Lisp compiler. If the returned title is not
the tool you asked for, that is zero coverage, not a near miss — go to the man
page. Verified 2026-08-22.

## Assert against live state, never against constants

Postconditions resolve values at run time. `sbctl verify`, not a path under
`/var/lib/sbctl/`. `blkid`, not the UUID from the last build. Anything that
varies per machine or per rebuild cannot be a literal in a step record.

Both halves of that decay. sbctl's key store is `/var/lib/sbctl/keys/` today
(measured — sbctl.8, read 2026-08-22); it moved there from an earlier location,
breaking the mkinitcpio signing hook for anyone holding the old path
(inherited-unverified — reported in the `_source/` research document, not
re-checked). A UUID copied from a previous install is worse than a stale path:
it is wrong *and* it is an unredacted identifier.

## Ground claims in `state/`, not in `_source/`

`arch-thinkpad/_source/` holds the documents being refactored away — inputs,
not current documentation, and wrong in known places: the PRD specifies the DNS
config ADR-0005 rejects, and files Secure Boot and TPM2 under "Deferred" when
both were applied 2026-08-15. Resolve every factual claim against `state/*.md`,
which is collector output. What `state/` cannot confirm is `inferred`.

## Never commit `redact.map`

`*/collect/redact.map` maps real identifiers to the `<TOKEN>` placeholders in
state files. With it, every redaction is reversible. Gitignored, and a
pre-commit hook blocks staged UUIDs, MACs, and Tailscale addresses.

Hand-written documents use the same placeholders — `<MACHINE_ID>`, `<TS_IPV4>`,
`<TS_IPV6>`, `<FSUUID_nvme0n1p2>`, `<NVME_SERIAL>`. The `_source/` documents were
redacted 2026-08-22; nothing derived from them may reintroduce a raw identifier.
Redact rather than `--no-verify`.

## Navigation

Read `_index.md`, then the relevant folder index. Do not read the whole vault.

## Activate the redaction gate in every clone

The pre-commit hook lives in `.githooks/` and is inert until this is run once
per clone:

    git config core.hooksPath .githooks

Nothing enforces it; `arch-thinkpad/collect/collect.sh` warns on stderr when it
is unset, and the hook refuses to run if its pattern set drifts from
`arch-thinkpad/collect/redact.sh`.
